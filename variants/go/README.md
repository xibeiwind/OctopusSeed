# 变体：Go

`-Stack go` 时被叠加。原则同其它变体：**能用构建期错误表达的约束，就不要只写在文档里**。

## 落地内容

| 文件 | 作用 |
|---|---|
| `jobs/go.yml` | CI 主门禁线：`gofmt -l`（不得有输出）/ `go vet ./...` / `go build ./...` / `go test ./... -count=1` |

## 把约束编进构建（建议起步值）

1. **vet 即门禁**：`go vet ./...` 的输出**必须**让 CI 失败；本地建议 `go vet ./...` 作为提交前动作。
2. **格式零漂移**：`gofmt -l .` 有输出即失败（等价于"零新增警告"）。
3. **测试不得靠缓存**：CI 用 `-count=1`，否则"上次过了"会伪装成"这次也过"。
4. **可选加强**：`staticcheck ./...`（需额外安装）与 `golangci-lint run --timeout 5m`；
   若要引入，**阈值一律设为"零 finding"**，并把"暂不修的清单"写进 `docs/范围边界清单.md` 而不是就地放宽。
5. **竞态**：并发代码建议在 CI 加 `go test -race ./...`（耗时翻倍，按需开启）。

## 与流程规范的衔接

- **提交前缀、编号、回填**照旧（与语言无关，见 `CONTRIBUTING.md` §1~§5）；
- Go 模块路径/包名与"能力归属"的对应关系，建议在 `docs/02-总体设计.md` 里写明——
  否则能力专题与代码会各说各话（`R-Plan-6`「同一事实只有一个权威处」）。
