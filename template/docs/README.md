## 一、分层与职责

| 层 | 文档 | 职责 | 变更频率 |
|---|---|---|---|
| **L0 入口** | 本文件 | 文档地图与路由 | 低 |
| **L1 基线** | `01-需求规格说明书.md` · `02-总体设计.md` | **跨能力共用契约**的唯一真相源 | 极低（锁定后不重编号） |
| **L2 能力专题** | `NN-Px-y-<主题>设计.md` | 单个能力**自包含**（背景 → 设计 → 契约归属 → DoD → 边界） | 实施期高 |
| **L3 过程** | 阶段计划 / 收口评审 / 报告 / `项目时间线.md` | 时间维度产物 | 阶段内高 |
| **L4 索引** | `需求跟踪矩阵.md` · `范围边界清单.md` | 追溯与开放项 | 每包一次 |

**归属原则（防"撒盐"）**：跨能力共用的契约 → 只住 `01`/`02`；单个能力的模型/端点/审计 → **只住能力专题**；上位层引用下位层时**只给链接、不复述要点**。详见 `CONTRIBUTING.md` §9.1 R-Plan-6。

## 二、按任务路由

| 我要… | 读这些 |
|---|---|
| **知道下一步做什么** | 当前阶段执行计划 §3/§4（见「三」） |
| 改**需求语义** | `01`（就地修订，不重编号）→ 回填 RTM |
| 改**接口 / 表 / 端点契约** | `02` 对应章节 → 能力专题 → 回填 RTM |
| **新增能力** | 先立能力专题 `NN-Px-y-*.md`（含"契约归属"节）→ 由 `01`/`02` 引用 |

| 查**范围外项** | `范围边界清单.md` |
| 追溯**需求 ↔ 工作包** | `需求跟踪矩阵.md` |
| 了解推进机制 / 门禁 | `CONTRIBUTING.md` §9 / §5 / §6 |
| 用模板起文档 | `模板/`（阶段执行计划 / 能力专题 / 阶段收口评审） |
